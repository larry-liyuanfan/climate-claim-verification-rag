# Coverage 获取策略：真实三路回归与选型结论

## 解决的问题与这轮决定

业务任务是帮助查证人员找到覆盖声明关系、时间和数量的可追溯证据。
本人实现检索表示适配、多阶段搜索，以及共用typed tools、预算和终答合同的获取对照。
本轮检验“显式关系coverage自报能否改变旧all-stop策略”，不是研究SOTA或生产验收。

精确批准的一次运行已完成96/96槽；**不采用该coverage自主策略**。
两次真实获取与后续文本送达成立，但大多数任务被coverage参数合同阻断，任务质量退化。
这个结果回答了具体实现选择，而不是新的Torch/权限故障或没有跑完。
不继续在同32题上改提示/放松校验后重跑求正数；搜索训练与排序仍是秋招主案例。

## 行为诊断与真实案例

[gold-free回放](verified-runs/coverage-regression32-behavior-20261003.json)覆盖全部96槽，
新诊断不生成答案、不重算官方分数，只读已回收轨迹。

- 自主90次gate：有效获取2、有效停止5、验证错误83（81coverage、2invalid JSON）。
  27/32执行失败。81个coverage失败attempt中，72含非当前可见句ID，
  21含非原claim逐字片段；原因重叠不能加成93次失败。该81次中0触发输出长度上限。
- 新增文本2次送达、2个任务、合计4句，并进入后续物理模型提示。
  `gate_received_new_full_text=6`包括修复，是6次gate调用，不是6次获取或6个任务。
- 按冻结顺序第6题（零基位置5）：自主query送达1句，修复后合法stop并生成终答；
  最终引用选择**未选择新增句**。不能据此推断新增文本完全没有影响推理，也不能宣称有效补证据收益。
- 第11题（零基位置10）：自主read送达3句并进入后续gate，最终repair exhausted，无终答。
  这是“送达成功但后续合同失败”，不是工具错误或成功Agent。
- 固定/工作流分别59/58次额外文本送达，都进入后续提示；工作流有一次重复引用参数修复。
  本批没有真实empty query或工具执行错误；不拿合成测试补作实测案例。

实现教训：把辅助coverage自报中的精确span/句ID绑定当成整个动作的硬门，
会在后续动作/终答验证与执行前阻断流程；不据此认定被拒动作本身合法。
若以后扩展，应单独研究“可验证动作引用”与“非权威coverage注释”的分离，而不是绕过引用安全校验。
这只是下一设计方向，**本轮没有部署新修复或证明其收益**。

## 两分钟STAR与求职口径
