# Climate 秋招展示包：训练、证据搜索与选型

**交付定位：**检索模型训练与可信证据搜索。用于大模型应用算法岗位中
检索、训练与效果选型的深挖，不以新增自主 Agent 成功作为投递前置条件。
本包无模型重跑、再训练、封存 test 或新的云端成本。

## 1. 两分钟展示怎么运行

默认无需语料、模型、GPU、网络或云：

```powershell
.venv-validation/Scripts/python.exe -X utf8 scripts/demo_recruitment_case.py
```

它回放已核验训练/排序汇总和本轮公开 BM25 的脱敏检索元数据。
Git 只保留手工查询、结果 ID/rank/score 与原文哈希，不发布证据原文。
**不是实时 LTR/dense/LLM 查证。**历史 LTR 权重与该 126-query 逐查询
候选轨迹当前未找到本地副本；不推断远端丢失，不重新训练冒充恢复。

本机可运行真正的公开语料 CPU 检索（仅 BM25，无模型推理）：

```powershell
.venv-validation/Scripts/python.exe -X utf8 scripts/demo_recruitment_case.py --evidence E:/Project/_climate_transfer/fair-three-arm-20261003/cpu-input/evidence.jsonl
```

该入口只接受已登记的 5,240 篇公开 evidence corpus SHA；查询为已有的
两条手工主题查询和一条 OOV 查询，不读取 claims/gold 或任何 test。
本轮实跑的 3 个证据包与旧公共展示的 ID/文本哈希一致。
输出说明空结果，不生成 verdict；OOV 是人为接口演示，**不是真实模型
空结果恢复案例或评测题**。

静态单页保存在本机 `artifacts/recruitment-demo-20261003.html`，不入 Git。
干净 checkout 可运行 `--format html --output artifacts/recruitment-demo.html`
生成脱敏回放页；加上已登记的 `--evidence` 则在本地显示完整公共证据。
本机交付页的训练/选型是历史回放，证据部分由本轮真实 BM25 入口生成。
它无服务、外部请求或自动运行。中文 UTF-8、HTML 转义和内容结构经过
差量检查；浏览器工具禁止本地 file URL，未声称通过浏览器视觉验收。
命令行展示是本包已实际验证的主要入口。

## 2. 一页架构与本人模块

```text
训练证据轨：已有候选 → hard negatives → claim 分组 → InfoNCE / LoRA
                                             ↓
                           20-step 任务适配与配对 offline-dev 评测

搜索证据轨：BM25 + dense/HNSW → 同一 RRF Top100 → LTR / 4B Top20 / 4B Top100
                                             ↓
                           validation 质量、时延、内存和不确定性选型

查证探索轨：初始证据 → 共享 read/query/rerank → 证据送达 → 终答/弃答/引用
                                             ↓
                           96 槽真实开发对照：当前自主策略不推广

当前 CPU 展示：历史汇总回放 + 真正公开 BM25 检索（不加载上面训练权重）
```

这些是相互关联但**不同数据/运行协议的证据轨**，不是一次模型运行
同时完成全部箭头。原课程团队系统是输入基础，不能全部归为本人独立开发。
个人扩展的重点是训练数据与负样本、配对评估、排序选型和有界证据协议。

| 面试深挖模块 | 代码入口 | 应能解释的技术判断 |
|---|---|---|
| hard-negative mining | `src/climate_rag/negatives.py:mine_hard_negatives` | 合并 BM25/dense 的高排名非 gold，保留来源/rank，排除已知正例；未标注真证据仍可能是 false negative |
| 训练数据与 InfoNCE | `src/climate_rag/embedding_training.py:build_swift_infonce_dataset` | 同 claim 的多正例不跨 train/eval；去已知 gold ID/重复文本，正例或负例不足不静默补造；claim-ID grouping 不是“所有语义近重复绝无泄漏”的证明 |
| RRF 与 LambdaMART | `src/climate_rag/fusion.py` | 11 个固定特征、缺路 rank 的定义、候选宽度一致；公共轨的连通分组与封存 test 独立管理 |
| 查询/补读/重排 | `src/climate_rag/fair_acquisition.py` | 共享工具/可见信息/终答合同与预算，送达文本不同于反馈收益 |
| 面试展示 | `scripts/demo_recruitment_case.py` | 历史指标与当前可运行算法分别标注，不用 fixture 或 CPU 检索认领大模型效果 |

LoRA 更新低秩参数，InfoNCE 拉近 query-positive 并与 hard negatives 竞争。
20 steps 只证明本次任务适配实验，不能扩成大规模预训练。
相同 claim 多正例分组、public 连通分区和 test 消费记录是不同层面的约束。
历史 frozen test 已被消费，状态照实保留；本轮不读取、推理或重新评测它，
不能称从未使用的独立留出。不要把一个函数的 ID 分组夸大成全部防泄漏措施。

## 3. 固定保存样本的语义诊断

选择已冻结 fair run 顺序前 12 个 unique tasks，覆盖三路全部 36 个输出，
不是挑正例或按分数抽样。检查完整 claim、所有引用与当时可见文本，
不读 gold、不运行模型、不替换原官方评分。

这是 **assistant 作者辅助诊断**，不是人工盲标、独立 test、语义准确率
或新泛化评测。按完整复合命题检查主体、关系、量词、时间和数字；
部分相关不等于支持全部判断。不充分也不等于命题/返回 label 必然为假。
相对时点或指代无法确定时保留不确定。

| 诊断（36 个输出） | 数量 |
|---|---:|
| 引用未充分建立整个返回判断 | 27 |
| 因命题范围/上下文不能审定引用支持 | 4 |
| 弃答与可见 packet 一致 | 4 |
| 弃答仍受上下文不确定限制 | 1 |

初始 packet 的 12-task 诊断：6 不足、4 部分覆盖、2 不确定。
不能写成代表性证据不足率，不能推出“强制获取就会成功”。
三路标签输出各有 9 个被判完整支持不足，不据此宣称路线等效或优劣。
原 32-task 三路官方结果、分母、bootstrap 与成本保持不变。
[仅聚合的诊断记录](verified-runs/recruitment-semantic-diagnosis-20261003.json)
保留选择/私密笔记哈希；逐任务原文和判断细节仅留在本地私密 transfer 目录。

**改变的实现决定：**不再将“多调用工具”设为本轮目标。主题、年份或
单个数字命中不能替代比较关系；补到更多文本也未必让终答引用充分。
若以后单独研究，应验证命题槽位覆盖与终答充分性，而不是换提示措辞
在已消费同批题上追正数。本包不追加这一研究。

## 4. 三段可防守案例

### A. 训练不是换大模型

**问题：**高排名非 gold 往往与声明主题很像，随机负例太容易。
**本人方法：**合并 lexical/dense 候选挖 hard negatives，按 claim 聚合正例，
排已知正例/重复文本，以 InfoNCE/LoRA 做任务适配并配对比较。
**结果：**百万语料、154 条 offline dev 上 R@5 27.93%→29.70%，
5,000 次配对区间为正。
**取舍：**短适配、开发集结果；原受限轨迹当前远端不可访问，保留已有
汇总而不重算冒充恢复。不是独立 test 或线上 A/B。

### B. 不按参数量选排序器

**问题：**同一候选集上更深重排的质量是否值得时延代价。
**本人方法：**固定 126-query validation、Top100 候选池，比较 LTR 与
4B 两种重排宽度，并同时看 bootstrap、完整请求时延和内存。
**结果：**LTR R@5 60.54%、离线 P95 77.8ms；4B Top100 为62.75%、9.30s，
但 R@5/F1 差值区间跨零。
**取舍：**选择 LTR 为低时延候选，保留 Top100 为离线质量选项；
不称统计等效、生产默认、在线 SLA 或美元节省。历史完整路线仍使用 GPU encoder。

### C. 引用格式正确不代表查证完成

**问题：**实体/背景匹配的句子可能没有支持所问的时间、倍数或比较关系。
**真实观察：**固定顺序样本中，行业数量比较缺少同口径分母；序列比较
被一般变暖背景替代。三路都会出现这类不足，补到新文本不能自动解决。
另一个语境不匹配的样本，三路都实际弃答，与当时可见 packet 一致。
**本人决定：**保留“合理弃答（作者局部判断）”及关系覆盖失败，不把
合法引文、stop 或工具数量当效果。自主获取仍没有实际成功链，故不推广。
这些是保存轨迹的非逐字摘要，不是新造任务或独立评测。

## 5. 两分钟 STAR

**S：**气候声明查证不只是找相似句子，还要覆盖声明的对象、时间和比较关系。
原系统能检索，但训练收益、排序取舍和最终引用支持需要分开证明。

**T：**我在团队系统上负责检索训练与选型扩展，目标是提高证据召回，
并选择可解释的质量—时延方案，而不是盲目换大模型。

**A：**从 BM25/dense 高排名候选挖 hard negatives，按 claim 聚合训练正例，
用 InfoNCE/LoRA 适配检索表示；固定查询和候选，用配对 bootstrap 比较
召回与证据质量，再比较 LambdaMART 与不同宽度的 4B 重排。
我还实现共享 typed 获取协议，把工具执行、文本送达、终答和引用校验分开记录。

**R：**百万语料 offline dev 的 R@5 从27.93%到29.70%。公开 validation 中，
LTR 达到60.54% R@5、77.8ms离线P95；4B Top100更慢且Top5质量优势不稳定，
因此选择LTR为低时延候选。真实自主对照32次都停止，未证明获取收益。
固定保存样本也提示：引用相关并不等于完整支持。最终交付训练与选型案例、
可重复公开检索展示及真实边界，不声称生产采用或自主效果。

## 6. 两条简历候选（不修改当前简历）

- **检索模型训练：**面向120.9万条气候证据，实现BM25/dense hard-negative
  mining与claim分组，采用InfoNCE/LoRA任务适配；在154条offline dev声明上
  将Recall@5从27.93%提升至29.70%，通过5,000次配对bootstrap验证。
- **搜索质量与时延选型：**固定公共validation查询与候选池，对比LambdaMART
  和4B精排，选定Recall@5为60.54%、离线P95为77.8ms的LTR候选；交付证据来源
  可追溯的检索展示，并将证据覆盖、引用合法性与判断正确性分开评估。

第二条没有把历史 LTR 指标当作新展示的实时效果。“展示”当前为实际 BM25
与历史选型回放；如被问到部署，明确没有复原历史 LTR 推理资产或上线默认。

## 7. 面试重点（只准备这六题）

1. 为什么用 hard negatives，如何排 false negatives？回答已知 gold、文本
   重复、未标注证据风险，不说负例一定为假。
2. InfoNCE 的温度和 LoRA 改了什么？能写损失和梯度竞争直觉，区分
   训练步骤、参数更新范围与评测集合。
3. 同 claim、多证据和 public 连通分组怎么防泄漏？区分 ID 分组与
   同义/共享证据连接，不能把已消费 validation 说成独立 test。
4. RRF 与 LambdaMART 解决什么，候选宽度为何影响结果？排序器不能召回
   不在 pool 的 gold；Top20 的尾部保留不等于尾部可进 Top5。
5. 为什么没选择4B？给质量差值区间、离线P95和内存，不以“更快”称全局更优。
6. Agent为什么32次stop？只能定位到实际获取决策边界；当前不能证明
   是参数量、提示词或环境根因。哪些证据能改变下一步？命题/引用关系覆盖，
   而不是加工具次数。没有自主成功轨迹就不认领能力。
